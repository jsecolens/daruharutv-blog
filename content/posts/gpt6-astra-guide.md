요즘 AI를 사용하면서 가장 놀라는 순간은 답변이 잘 나올 때만은 아닙니다. 무언가를 부탁했는데, AI가 자료를 찾아보고 파일을 만들고 화면까지 확인하면서 일을 진행할 때입니다. 저도 아스트라를 쓰면서 "이제는 설명해주는 것에서 실제로 처리해주는 쪽으로 넘어가고 있구나"라는 생각을 하게 됩니다.

그런데 막상 사용하려고 하면 헷갈립니다. GPT-6 아스트라는 챗GPT와 다른 프로그램일까요? 코덱스에서만 쓰는 걸까요? Light와 High는 얼마나 다르고, Max를 선택하면 무조건 더 좋은 결과가 나올까요?

오늘은 어려운 성능 점수보다, 실제로 사용하는 입장에서 알아두면 좋은 내용을 정리해보겠습니다.

## 아스트라는 AI 모델의 이름입니다

GPT-6 Astra, 즉 아스트라는 OpenAI의 AI 모델입니다. 질문을 이해하고, 자료를 해석하고, 작업 방법을 판단하는 핵심 부분이라고 생각하면 됩니다. 공식 설명에서는 복잡한 문제 해결, 코딩, 조사, 문서 제작, 컴퓨터 사용 등을 주요 활용 분야로 소개합니다.

이름이 여러 개라 복잡하다면 세 가지를 나눠보면 편합니다.

| 이름 | 쉽게 이해하면 |
| --- | --- |
| GPT-6 아스트라 | 작업을 이해하고 판단하는 AI 모델 |
| ChatGPT·Work·Codex | 그 모델과 대화하거나 일을 맡기는 서비스와 작업 환경 |
| 브라우저·파일·컴퓨터 조작 도구 | AI가 실제 작업에 사용하는 기능 |

같은 아스트라를 사용하더라도 어떤 도구가 연결되어 있는지에 따라 할 수 있는 일이 달라집니다. 모델 선택만 바꿨다고 컴퓨터의 모든 파일과 프로그램에 접근할 수 있는 것은 아닙니다.

따라서 "아스트라가 이것까지 할 수 있나요?"라는 질문에는 모델 성능뿐 아니라 지금 어느 화면에서, 어떤 기능을 연결해 쓰고 있는지도 함께 살펴봐야 합니다.

## 어디서 사용할 수 있나요?

공식 모델 안내에는 ChatGPT 웹과 데스크톱 앱, Codex의 여러 사용 환경, API가 소개되어 있습니다. 다만 실제 선택 가능 여부는 요금제, 앱 버전, 배포 상황, 조직 설정에 따라 달라질 수 있습니다.

처음이라면 다음처럼 목적부터 정하는 것이 좋습니다.

일반적인 질문이나 설명이 필요하다면 ChatGPT에서 시작하면 됩니다. 내가 사용하는 화면의 모델 선택 메뉴에 Astra가 있는지 확인합니다. 화면에 보이는 이름을 확인하는 것이, 단순히 채팅창에 "아스트라처럼 답해줘"라고 적는 것보다 정확합니다.

자료를 바탕으로 완성된 결과물이 필요하다면 Work를 살펴보면 됩니다. 공식 안내는 일반 Chat을 설명·아이디어·짧은 초안에, Work를 문서·분석·파일처럼 검토할 수 있는 결과물을 만드는 작업에 사용하는 방식으로 설명합니다.

프로그램을 만들거나 기존 코드를 수정하려면 Codex가 적합한 출발점입니다. 컴퓨터에 명령어를 입력하는 방식인 CLI나 코드 편집기에 붙이는 확장 기능 등에서도 사용할 수 있습니다. 개발 경험이 없다면 처음부터 모든 방식을 설치할 필요는 없습니다.

API는 내가 만드는 서비스가 아스트라를 호출하도록 연결하는 개발자용 방식입니다. 일반 사용자는 웹이나 앱에서 먼저 활용해봐도 충분합니다.

## 실제로 무엇을 맡길 수 있을까요?

활용 범위를 이해할 때는 "무슨 질문에 답할까?"보다 "어떤 결과물을 받고 싶은가?"로 생각하면 좋습니다. 다음은 지원되는 파일·검색·개발 도구가 연결된 환경에서 시도해볼 만한 요청 예시입니다. 모든 계정에서 같은 기능이나 완성도가 보장된다는 뜻은 아닙니다.

### 흩어진 자료를 보고서와 비교표로 정리하기

견적서 세 개를 받았다고 가정해보겠습니다. 예전에는 각 파일을 번갈아 열며 가격, 포함 항목, 납기, 유지관리 조건을 옮겼습니다. 이제는 관련 파일을 제공하고 비교 기준과 결과물 형태를 정해 요청해볼 수 있습니다.

> 첨부한 견적서 세 개를 비교해주세요. 총액, 포함 항목, 제외 항목, 납기를 표로 정리하고, 자료에 없는 내용은 추정하지 말고 '확인 필요'로 표시해주세요. 마지막에는 업체에 다시 물어볼 질문을 적어주세요.

여기서 중요한 것은 가장 싼 업체를 AI가 대신 결정하는 일이 아닙니다. 사람이 판단하기 전에 놓치기 쉬운 조건을 한눈에 볼 수 있게 만드는 것입니다. 가격이 같아도 설치비가 빠져 있거나, 유지관리 기간이 다르면 결론이 달라질 수 있습니다.

### 문서나 발표 자료를 실제 파일로 만들기

보고서의 목차만 받아보는 것과 편집 가능한 파일을 받는 것은 편의성에서 차이가 큽니다. Work는 파일과 도구를 이용해 검토할 수 있는 결과물을 만드는 작업을 지원합니다.

요청할 때는 "발표 자료 만들어줘"에서 한 발 더 나아가면 좋습니다. 발표 대상, 발표 시간, 반드시 들어갈 내용, 파일 형식을 알려주는 것입니다.

예를 들어 "처음 보는 사람에게 설명하는 10분 발표이니 어려운 용어를 줄이고, 핵심 내용을 8장으로 구성해주세요"라고 요청할 수 있습니다. 마지막에는 표의 숫자, 잘린 글자, 이미지 배치까지 확인해달라고 덧붙이면 검토 기준도 분명해집니다.

### 작은 프로그램을 만들고 고치기

파일 이름을 일괄 변경하는 도구, 개인 수집 목록, 반복 업무 체크 화면처럼 범위가 분명한 프로그램부터 시작해볼 수 있습니다. 아스트라는 여러 단계의 개발 작업을 수행하도록 설계된 모델입니다.

처음부터 거대한 서비스를 요청하기보다는 "자료를 입력하고 저장한 뒤 다시 열어볼 수 있는 화면"처럼 작게 완성해보는 편이 결과를 판단하기 쉽습니다. 무엇이 잘못됐는지 설명할 때도 "안 돼요"보다는 "저장 버튼을 누르면 목록에 나타나지만 새로고침하면 사라집니다"가 훨씬 유용합니다.

## 정말 내 컴퓨터를 직접 조작하나요?

지원되는 환경에서는 가능합니다. 다만 웹사이트를 조작하는 기능과 내 PC에 설치된 앱을 조작하는 기능은 구분해야 합니다.

브라우저 기능은 웹페이지를 열고, 정보를 확인하고, 여러 단계의 사이트 작업을 진행하는 데 쓰입니다. 공식 안내에 따르면 ChatGPT 웹과 데스크톱 앱에서 브라우저를 사용할 수 있지만, 같은 내장 브라우저 기능이 Codex CLI나 IDE 확장에 그대로 제공되는 것은 아닙니다.

내 컴퓨터의 앱 화면을 보고 조작하려면 데스크톱 앱의 Computer Use 기능과 필요한 권한이 갖춰져야 합니다. 공식 문서는 지원 지역의 macOS와 Windows에서 Work·Codex를 통한 사용을 안내합니다.

즉, 웹에서 파일을 만들어줬다고 내 컴퓨터의 엑셀을 직접 열었다고 생각할 필요는 없습니다. 별도 작업 공간에서 파일을 생성했을 수도 있습니다. 반대로 실제 PC 앱을 조작하도록 연결했다면 변경 내용이 내 작업 환경에 영향을 줄 수 있으므로 범위를 분명히 정하는 것이 좋습니다.

처음에는 "이 파일의 복사본만 수정해주세요", "입력 초안까지 만들고 제출 직전에 멈춰주세요"처럼 확인 지점을 정해보세요. 화면이 움직이는 모습보다 최종적으로 무엇이 저장되었는지가 중요합니다.

## Light부터 Max까지 다섯 단계는 무엇이 다른가요?

이 설정은 같은 아스트라에게 한 작업을 얼마나 깊게 검토하고 풀도록 할지 조절하는 추론 강도입니다. 다섯 개의 서로 다른 모델을 번갈아 사용하는 것으로 이해할 필요는 없습니다.

공식 API의 기본 단계는 Low·Medium·High·Extra High·Max이며, 일부 앱에서 Low는 Light로 표시됩니다. 아래의 작업 예시는 단계 차이를 이해하기 위한 활용 제안입니다.

| 단계 | 쉽게 이해하면 | 시도해볼 만한 작업 |
| --- | --- | --- |
| Light / Low | 범위가 분명한 일을 비교적 가볍게 처리 | 문장 수정, 짧은 내용 정리, 정해진 항목 추출 |
| Medium | 속도와 검토 깊이 사이의 균형 | 여러 자료를 묶은 초안, 비교표, 작은 작업 계획 |
| High | 조건과 판단할 부분이 많은 일을 더 깊게 검토 | 복잡한 문서 비교, 여러 조건이 얽힌 작업 |
| Extra High / xhigh | 여러 단계의 어려운 문제에 더 많은 추론 투입 | 까다로운 오류 원인 분석, 정밀한 자료 대조 |
| Max | 속도보다 깊이가 중요한 문제에 최대 수준의 추론 투입 | 다른 설정으로 해결되지 않는 고난도 문제 재검토 |

낮은 단계라고 대충 쓰는 모드, 높은 단계라고 정답 보장 모드가 되는 것은 아닙니다. 시간이 더 걸리는 대신 얻는 개선이 내 작업에서 충분한지를 살펴보면 됩니다.

가령 안내문에서 존댓말만 통일하는 일과, 서로 다른 다섯 자료의 모순을 찾아 하나의 계획으로 만드는 일은 필요한 검토량이 다릅니다. 둘을 모두 Max로 처리할 이유는 크지 않습니다.

공식 선택 가이드도 같은 자료로 설정을 비교해보고, 필요한 품질을 충족하는 가벼운 설정을 찾는 방식을 권합니다. 저는 이를 "처음부터 최대치"보다 "결과를 보며 필요한 만큼 높이기"로 이해하면 좋겠다고 생각합니다.

---

## Ultra가 보이면 여섯 번째 단계인가요?

일부 환경에서는 Ultra도 보일 수 있습니다. Max는 한 작업의 추론에 더 많은 시간을 쓰는 설정이고, Ultra는 여러 보조 에이전트가 작업을 나눠 진행하는 방식입니다. 따라서 기본 다섯 단계와 구분해서 이해하는 편이 정확합니다. 표시 여부는 사용하는 앱과 설정에 따라 다릅니다.

비유하자면 어려운 문서 하나를 더 오래 검토하는 것과, 나눌 수 있는 자료 조사를 여러 담당자에게 분담하는 것의 차이에 가깝습니다. 일이 작거나 각 단계가 앞 단계의 결과에 의존한다면, 여러 작업으로 나누는 것이 꼭 유리하지는 않겠지요.

---

## 높은 설정을 쓰면 사용량도 달라지나요?

복잡하고 오래 걸리는 작업은 사용량을 더 많이 소비할 수 있습니다. 첨부 자료, 대화 길이, 도구 사용, 추론 설정이 함께 영향을 주므로 "질문 한 번이면 항상 같은 양"으로 계산하기 어렵습니다. Work와 Codex의 사용량도 공유됩니다.

2026년 9월 공식 요금 안내에는 Plus·Pro·Business 등의 아스트라 사용량 예시가 있지만, 고정 질문 횟수를 보장하는 표는 아닙니다. 실제 계정의 모델 메뉴와 사용량 화면을 확인하는 것이 정확합니다. API를 사용하는 경우에는 ChatGPT 구독과 구분되는 사용량 기반 요금이 적용됩니다.

또 하나, 추론을 높이는 것과 최신 정보를 검색하는 것은 별개입니다. Max로 설정했다고 오늘 발표된 공지까지 저절로 알고 있는 것은 아닙니다. 최신 정보가 필요하면 검색 가능한 환경에서 공식 원문을 찾아 확인하도록 요청해야 합니다.

## 어디까지 맡기고, 무엇을 직접 확인하면 좋을까요?

저는 AI 활용 범위를 단순히 "할 수 있다, 없다"로 나누기보다 검토 방법까지 함께 생각하는 편이 좋다고 봅니다.

글의 초안은 읽으며 고칠 수 있고, 표는 원본 숫자와 비교할 수 있으며, 프로그램은 실제 입력값으로 실행해볼 수 있습니다. 반면 외부에 보내는 문서나 되돌리기 어려운 변경은 잘못되었을 때의 영향이 큽니다. 작업은 맡기더라도 최종 확인 지점을 남기는 이유입니다.

처음 시작한다면 아래처럼 요청해보세요.

> 첨부한 자료만 사용해 비교표와 한 페이지 요약을 만들어주세요. 확인되지 않은 내용은 표시하고, 원본 파일은 유지해주세요. 결과물을 만든 뒤 제가 확인할 숫자와 항목을 짚어주세요.

좋은 요청은 반드시 길 필요가 없습니다. 어떤 자료로, 어떤 결과물을, 어느 범위까지 만들면 되는지가 분명하면 됩니다.

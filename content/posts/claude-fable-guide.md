AI를 고르려고 들어갔는데 모델 이름이 너무 많아서 더 헷갈릴 때가 있습니다. 클로드도 마찬가지입니다. 소넷, 오퍼스에 이어 페이블이라는 이름이 보이니 "클로드와 페이블은 다른 서비스인가?", "클로드 코드까지 설치해야 사용할 수 있나?" 하는 궁금증이 생깁니다.

저도 AI를 계속 사용하고 있지만, 성능이 좋아지는 속도만큼 사용 방법과 설정도 빨리 달라진다는 생각이 듭니다. 좋다는 이야기를 듣고 선택했는데, 어디에서 무엇을 맡겨야 그 차이를 알 수 있는지부터 막막할 수 있습니다.

이번에는 클로드 페이블을 처음 접하는 분도 이해할 수 있도록, 모델의 의미부터 사용할 수 있는 곳, 요금과 설정, 실제 업무에 적용하는 방법까지 살펴보겠습니다.

## 페이블은 클로드에서 사용하는 AI 모델입니다

클로드는 Anthropic이 제공하는 AI 서비스이고, Fable은 그 안에서 선택할 수 있는 모델 계열입니다. 별도의 '페이블 프로그램'을 설치해야 한다는 의미는 아닙니다.

2026년 9월 공식 소개의 중심은 Claude Fable 5.1입니다. 페이블 5와 5.1이 함께 언급되기도 하므로, 화면에 단순히 Fable이라고 적혀 있다면 실제 선택된 버전도 확인하는 것이 좋습니다. 공식 소개는 긴 시간 이어지는 복잡한 작업, 개발, 자료 분석과 문서 중심 업무를 주요 활용 분야로 제시합니다.

쉽게 말하면 질문 한 개에 답하는 것뿐 아니라, 여러 자료와 도구를 이용해 하나의 결과물을 완성하는 작업에 초점을 둔 모델입니다.

다만 "상위 모델이니 모든 질문에서 무조건 더 좋다"는 식으로 생각할 필요는 없습니다. 짧은 문장 하나를 고치는 일과 수십 개의 조건을 대조하는 일에서 체감 차이는 다를 수 있습니다. 내가 어떤 일을 맡기려는지부터 정하는 것이 먼저입니다.

## 어디서 사용할 수 있나요?

공식 안내는 페이블을 웹, 모바일, 데스크톱, Cowork, Claude Code 등에서 사용할 수 있다고 설명합니다. 일반 사용자는 클로드의 모델 선택 메뉴에서 Fable 5 또는 Fable 5.1을 확인하면 됩니다.

각각의 역할은 다음처럼 이해하면 쉽습니다.

| 사용하는 방식 | 어떤 때 살펴보면 좋을까? |
| --- | --- |
| 클로드 웹·앱에서 대화 | 글을 다듬거나 자료를 읽고 질문할 때 |
| Cowork의 작업 기능 | 파일과 도구를 이용해 여러 단계의 일을 맡길 때 |
| Claude Code | 프로그램을 만들거나 기존 코드의 문제를 해결할 때 |
| Claude API | 내가 만든 서비스 안에 페이블을 연결할 때 |

여기서 페이블은 작업을 판단하는 모델이고, Cowork나 Claude Code는 일을 수행하는 환경에 가깝습니다. 모델을 바꿨다고 자동으로 내 PC 전체를 읽거나 모든 외부 서비스에 접속하게 되는 것은 아닙니다.

최근에는 화면 변화도 있습니다. 공식 도움말에 따르면 일부 Pro·Max 계정에는 Chat과 Cowork를 통합한 경험이 순차 적용되고 있습니다. 해당 화면에서는 Cowork 버튼을 따로 고르지 않고 원하는 작업을 설명하는 방식으로 시작합니다. 따라서 예전 설명에 있던 버튼이 안 보인다고 곧바로 기능이 없다고 판단할 필요는 없습니다.

## Pro를 결제했다면 페이블도 추가 비용 없이 쓰나요?

이 부분은 사용 전에 꼭 구분할 필요가 있습니다. 사용할 수 있는 요금제라는 것과 기본 구독 사용량에 포함된다는 것은 다릅니다.

2026년 9월의 공식 페이블 사용 안내는 다음과 같이 설명합니다.

| 이용 조건 | 페이블 5·5.1의 사용 방식 |
| --- | --- |
| Pro, Team의 일반 좌석 | 기본 구독 사용량에 포함되지 않으며 사용 크레딧으로 과금 |
| Max, Team의 프리미엄 좌석 | 주간 전체 사용 한도의 최대 50%까지 페이블에 사용 가능 |
| Enterprise | 좌석 종류와 계약·과금 방식에 따라 다름 |
| API | API 사용량에 따라 과금 |

Max에서 안내하는 50%는 별도로 50%를 더 주는 의미가 아닙니다. 전체 주간 한도 안에서 페이블에 쓸 수 있는 범위이며, 다른 모델도 같은 전체 한도를 사용합니다. 한도 이후 추가 크레딧으로 계속 사용할 수 있는지는 계정의 결제 설정을 확인해야 합니다.

예전 무료 제공이나 프로모션을 설명한 글만 보고 결제하기보다는, 현재 모델 선택창과 사용량 화면에서 추가 과금 표시를 확인하는 것이 좋겠습니다. 긴 작업을 자주 맡길 생각이라면 한 번의 답변 품질뿐 아니라 작업을 마칠 때까지 얼마나 사용하는지도 함께 봐야 합니다.

## 어떤 일을 맡겨보면 좋을까요?

페이블의 공식 소개는 여러 앱에 걸친 작업, 복잡한 코드 수정, 문서 속 표와 그림 이해 등을 설명합니다. 아래는 그런 기능을 실제 생활과 업무에 적용해볼 수 있는 요청 예시입니다. 필요한 도구와 접근 권한이 갖춰진 환경을 전제로 합니다.

### 긴 자료를 읽고 '지금 무엇을 해야 하는지' 정리하기

긴 공고나 안내문을 받았을 때 단순 요약만으로는 부족한 경우가 있습니다. 문서가 짧아졌지만, 정작 내가 무엇을 준비해야 하는지는 여전히 헷갈리는 것입니다.

그럴 때는 결과를 행동 단위로 정해 요청해보면 좋습니다.

> 이 안내문에서 신청 대상, 제출 자료, 마감일, 제출 방법을 정리해주세요. 제가 준비할 순서대로 체크리스트를 만들고, 본문과 첨부 양식의 설명이 다른 부분은 따로 표시해주세요. 파일에 없는 조건은 만들어 넣지 말아주세요.

이런 요청의 장점은 요약문을 읽고 다시 할 일을 뽑는 단계를 줄인다는 것입니다. 마지막에는 체크리스트의 각 항목이 원문 어디에 있는지도 확인하면 좋습니다. 특히 마감일이나 제출 서류는 짧은 문장 하나를 놓쳐도 결과가 달라질 수 있습니다.

### 여러 파일을 함께 보고 일관성 확인하기

보고서와 발표 자료를 따로 수정하다 보면 제목은 같지만 수치나 일정이 서로 달라지는 일이 생깁니다. 한 파일만 열어보면 자연스러워 보여도, 함께 비교하면 오류가 드러날 수 있습니다.

> 보고서와 발표 자료를 비교해주세요. 사업 기간, 예산, 목표 수치, 용어가 서로 다른 부분을 찾아 표로 만들어주세요. 어느 쪽이 맞는지 판단할 근거가 없으면 제가 확인할 항목으로 남겨주세요.

AI에게 곧바로 정답을 결정하게 하기보다 서로 맞지 않는 부분을 먼저 찾게 하는 방식입니다. 자료가 복잡할수록 이런 중간 결과물이 유용합니다. 사용자는 확인할 부분에 집중할 수 있고, 수정 이유도 더 분명하게 남길 수 있습니다.

### 반복 업무를 처리하는 작은 도구 만들기

개발 지식이 많지 않아도 필요한 기능을 말로 설명하며 시작해볼 수 있습니다. 다만 처음부터 모든 기능을 넣기보다 사용 장면이 분명한 작은 도구가 좋습니다.

예를 들어 "엑셀을 올리면 중복된 항목을 표시하는 화면"이나 "수집품 목록에 사진과 메모를 저장하는 페이지" 같은 것입니다. 중요한 것은 멋진 첫 화면보다 실제로 자료가 저장되고 다시 열리는지입니다.

Claude Code에서는 모델 선택 명령인 `/model`로 사용 가능한 모델을 확인할 수 있습니다. 공식 문서의 `fable` 별칭은 일반적으로 5.1을 가리키지만 연결 환경에 따라 달라질 수 있으므로, 정확한 버전이 필요하면 모델 이름까지 확인해야 합니다.

처음 사용하는 분이라면 이 명령어부터 외울 필요는 없습니다. 웹이나 앱에서 작은 작업을 해보고, 실제 개발 파일을 다룰 필요가 생길 때 Claude Code를 알아봐도 됩니다.

## Cowork에서는 파일과 컴퓨터를 어디까지 다룰 수 있나요?

Cowork는 코딩 이외의 업무에도 여러 단계의 작업 기능을 제공하는 환경입니다. 사용자가 연결한 파일과 도구를 바탕으로 일을 진행하도록 설계되어 있습니다.

여기서 웹·모바일에서 작업을 시작하는 것과 내 컴퓨터의 파일을 직접 사용하는 것은 다릅니다. 공식 안내상 웹·모바일의 로컬 파일 접근, 브라우저·컴퓨터 사용은 Claude Desktop을 통해 연결됩니다. 연결한 PC 폴더를 클라우드 작업에서 사용하려면 데스크톱에서 시작한 세션이어야 하고, 해당 컴퓨터에서 앱이 열려 있어야 한다는 조건도 있습니다. 컴퓨터 화면을 직접 조작하는 기능은 Pro·Max의 베타 기능으로 안내됩니다. 휴대전화에서 요청했다고 PC의 모든 자료를 가져오는 것은 아닙니다.

처음에는 전용 작업 폴더에 자료의 복사본만 넣고 시작하는 편이 이해하기 쉽습니다. "어느 자료를 읽어도 되는지"와 "어디에 결과물을 저장할지"가 명확해지기 때문입니다. 공식 안전 안내도 필요한 폴더로 접근 범위를 좁히고 중요한 파일을 백업하는 방식을 권합니다.

특히 "정리해주세요"라는 표현은 구체화하는 것이 좋습니다. 문서 내용만 요약하라는 뜻인지, 파일 이름을 바꾸라는 뜻인지, 폴더를 옮기라는 뜻인지가 다를 수 있습니다. 결과를 확인한 뒤 실제 이동이나 변경으로 이어가면 서로의 이해가 맞는지 확인하기 편합니다.

## 페이블도 추론 단계를 선택할 수 있나요?

네. 페이블 5와 5.1은 Low·Medium·High·Extra High·Max의 추론 강도를 지원합니다. 쉽게 말해 작업을 얼마나 깊게 검토할지 조절하는 설정입니다.

아래 예시는 어떤 설정부터 시도할지 감을 잡기 위한 제안입니다.

| 단계 | 시도해볼 작업 |
| --- | --- |
| Low | 문장 수정, 짧은 질문, 범위가 명확한 정리 |
| Medium | 일반적인 문서 초안, 여러 자료를 묶은 정리 |
| High | 조건이 많은 비교, 복잡한 설명이나 작업 계획 |
| Extra High / xhigh | 오래 이어지는 개발·분석, 여러 단계의 문제 해결 |
| Max | 매우 어려운 문제나 충분한 시간을 들여야 하는 정밀 검토 |

공식 도움말은 추론 강도가 높아지면 더 오래 걸리고 사용량을 더 많이 소비할 수 있다고 설명합니다. 모델 이름 옆의 Effort 메뉴에서 설정하며, 계정이나 조직 정책에 따라 보이는 선택지는 달라질 수 있습니다.

페이블 5.1의 발표 안내에서는 기본값을 일반 클로드·Cowork에서는 Medium, Claude Code에서는 High로 설명했습니다. 실제 내 화면의 현재 설정이 우선이지만, 이것만 봐도 모든 작업에 Max를 쓰도록 설계된 것은 아니라는 점을 알 수 있습니다.

아스트라의 High와 페이블의 High를 같은 점수로 비교하는 것도 피하는 편이 좋습니다. 이름이 비슷해도 서로 다른 모델의 설정입니다. 같은 자료와 요청을 넣었을 때 결과가 얼마나 정확하고, 얼마나 수정이 필요한지로 비교하는 편이 현실적입니다.

## Thinking과 Effort는 같은 것인가요?

공식 도움말은 둘을 구분합니다. Effort는 응답에 들이는 검토 강도이고, Thinking은 답변 전 문제를 나누고 접근법을 검토하는 기능과 관련된 설정입니다. 페이블 5.1에서는 Thinking이 항상 켜져 있어 끌 수 없다고 안내합니다. 낮은 Effort를 고른다고 생각하는 기능 자체가 꺼지는 것은 아닙니다.

따라서 "생각을 오래 했으니 반드시 맞을 것"이라고 판단하기보다는 최종 결과를 확인해야 합니다. 충분히 검토해도 입력 자료가 잘못되었거나, 요구사항을 다르게 이해했다면 결과가 빗나갈 수 있습니다.

예를 들어 매출표에서 세금 포함 여부를 알려주지 않은 상태로 합계만 계산하게 하면, 계산이 맞더라도 우리가 원하는 숫자가 아닐 수 있습니다. 설정을 높이기 전에 이런 기준을 먼저 전달하는 편이 효과적입니다.

## 잘 쓰려면 모델보다 먼저 정할 세 가지

페이블을 처음 써본다면 복잡한 지시문을 외우기보다 다음 세 가지를 먼저 적어보세요.

첫째, 무엇을 받을지입니다. 요약문인지, 비교표인지, 실제 파일인지, 실행 가능한 프로그램인지 정합니다.

둘째, 무엇을 근거로 할지입니다. 첨부 자료만 사용할지, 최신 정보를 검색할지, 특정 양식을 따라야 하는지 알려줍니다.

셋째, 어디까지 완료하면 되는지입니다. 초안 작성, 파일 저장, 검토까지는 맡기더라도 외부 발송이나 공개 여부는 별도로 정할 수 있습니다.

이를 합치면 다음과 같은 요청이 됩니다.

> 첨부한 회의 메모를 기준으로 실행 계획을 만들어주세요. 결정된 일과 아직 논의 중인 일을 구분하고, 담당자나 날짜가 없으면 임의로 채우지 말아주세요. 마지막에 다음 회의에서 확인할 질문을 다섯 개 이내로 정리해주세요.

이런 작업부터 시작하면 모델의 성능을 막연히 감탄하는 데서 한 걸음 더 나아갈 수 있습니다. 실제로 내 시간을 얼마나 줄였는지, 어떤 부분은 다시 확인해야 하는지 알게 되기 때문입니다.

페이블을 잘 쓴다는 것은 항상 가장 높은 설정을 켜두는 일이 아닐 것입니다. 내 일이 무엇인지 설명하고, 필요한 자료를 주고, 결과를 판단할 기준을 갖추는 일에 더 가깝다고 생각합니다. 반복되는 작은 작업 하나를 끝까지 맡겨보면, AI에게 맡길 범위와 내가 직접 챙길 부분이 조금씩 선명해질 것입니다.
